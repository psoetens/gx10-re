# BOSS GX-10 — MIDI API reference

Reverse-engineered from BOSS Tone Studio for GX-10 (v1.0.0 build 43)
talking to a connected GX-10 over USB-MIDI. Cross-referenced with the
official **GX-10 Parameter Guide** (`docs/manuals/GX-10_Parameter_Guide.pdf`).

This is a top-level index. The detailed material lives in:

- **`docs/protocol.md`** — transport, USB IDs, SysEx framing (RQ1/DT1),
  top-level address regions, patch-select register encoding.
- **`docs/effects/all_effects.md`** — 81 effects × every knob, with
  byte address, byte min/max, knob count per TYPE/SP_TYPE/HARMONY.
  Auto-generated by `tools/build_effects_doc.py`.
- **`docs/effects/all_effects.json`** — same data, machine-readable.
- **`docs/bpm_encoding.md`** — BPM byte mapping (`V = BPM × 10`,
  4-nibble big-endian at `0x1000_0F02`).
- **`docs/menus.md`** — toolbar buttons, dialogs (CTL/EXP, IN/OUT,
  WRITE, MENU, TUNER), patch-load/save flow, FUNCTION enum.
- **`docs/manuals/GX-10_Parameter_Guide.pdf`** — Roland's official
  per-effect parameter list and TARGET enums. Used by
  `tools/manual_xref.py` to label captured knobs.

## Top-level address regions (from `protocol.md`)

| Region | Purpose |
|--------|---------|
| `0x0000_0000`+ | Global system block + patch-select register (5 B) |
| `0x0000_4000`–`0x0000_4FFF` | Hardware-settings region (AUTO OFF, EXP HOLD, GLOBAL EQ ON/OFF) |
| `0x0000_6000`–`0x0000_6FFF` | IN/OUT memory block (echo region for `0x0020_03xx` writes) |
| `0x0020_0000`+ | Editor I/O staging (INPUT type/sens, OUTPUT SELECT, GLOBAL EQ knobs) |
| `0x1000_0000` (~16 KiB) | **Live patch / edit buffer** — name + master block + 24 effect slots |
| `0x2000_0000`+ | Live-patch mirror (read-only) |
| `0x5000_0000`+ | Preset patch name table (296 names) |
| `0x6040_0000` (16 × 0x10000) | User patch slots — *not* directly written; populated by save command |
| `0x7F00_0000`+ | System status registers + tuner display stream + save trigger |

## Live patch buffer layout (`0x1000_0000`+)

| Offset | Address | Size | Content |
|--------|---------|------|---------|
| `0x000` | `0x1000_0000` | 16 B | Patch **name** (ASCII, space-padded) |
| `0x069` | `0x1000_0069` | 20 B | Patch metadata (date / memory# encoding — TBD) |
| `0xF00` | `0x1000_0F00` | 62 B | **Master block** (BPM, KEY, MEMORY LEVEL, INPUT SETTING, CARRYOVER, TEMPO HOLD) |
| `0xF02` | `0x1000_0F02` | 4 B  | **Master BPM** (`V = BPM × 10`, 4-nibble big-endian — see `bpm_encoding.md`) |
| `0x1000` | `0x1000_1000` | 0x100 | Per-memory CTL/EXP assignments (FUNCTION / MODE / PREFERENCE bytes) |
| `0x100` | `0x1000_001B` | 1 B | CTL1 FUNCTION (17-value enum — see `menus.md`) |
| `0x100` | `0x1000_001F` | 1 B | EXP1 SW FUNCTION (same enum) |
| `0x1100` | `0x1000_1100` | 0x103 | **Slot 0** parameter block |
| `0x1300` | `0x1000_1300` | 0x103 | **Slot 1** parameter block |
| … | … | … | … |
| `0x3700` | `0x1000_3700` | 0x103 | **Slot 19** parameter block (final) |

**Slot stride is 0x200**. Each slot's parameter block is 0x103 bytes:
- offset `+0x00`: effect-type byte (e.g. `0x08` = COMP, `0x02` = AMP)
- offset `+0x03`: sub-TYPE byte (popup-cycled enum, e.g. AMP TYPE 0..22)
- offset `+0x07`+: knob parameters (varies per effect)
- offset `+0x3B` (AMP family only): SP TYPE byte (AMP family)

AMP-style slots additionally have a 0x30-byte IR sub-block at offset
`+0x703` from the slot base (used for SP TYPE = ORIGINAL/USER1..16).

## Commands (from `protocol.md`)

All SysEx commands use the framing `F0 41 10 00 00 00 00 0B <cmd>
<addr:4> <data> <chk> F7`.

| Cmd | Name | Direction | Purpose |
|----:|------|-----------|---------|
| `0x11` | RQ1 | host→dev | Read (request 1) — request `<size:4>` bytes at `<addr>` |
| `0x12` | DT1 | both | Write or report — write `<data>` to `<addr>` |
| `0x40` | (other) | rare | (not used by Tone Studio) |

The address space is 28-bit (each of the 4 bytes is 7-bit). Reads in
the `0x1000_1xxx`–`0x1000_3xxx` range have a 0x40-byte chunk limit.

## Parameter knob encoding patterns

Most effect knobs use **single-byte** encoding (1 byte at the knob's
address, range `0x00..max`). Common patterns observed:

| Pattern | Used by | Example |
|---------|---------|---------|
| Single byte 0..15 | Most knobs (low-resolution params, bytes 0-15) | COMP SUSTAIN |
| Single byte 0..120 | DRIVE, GAIN | AMP GAIN |
| Single byte 0..100 | LEVEL, TONE, % parameters | AMP BASS |
| Single byte 0..1 | OFF/ON switches | BRIGHT SW |
| 4-nibble big-endian (V = display × 10) | BPM, TIME ms with BPM-sync | Master BPM at `0x1000_0F02` |
| 1-byte enum | TYPE / SP TYPE / MODE / FUNCTION / MIC TYPE | AMP TYPE 0–22 |

Decoded enums:
- **TUNER mode** at `0x0000_0007`: 1=MONO, 2=POLY, 3=TT MODE
- **CTL/EXP FUNCTION** at `0x1000_001B` (and per-controller offsets):
  17 values, table in `docs/menus.md`
- **HARMONY** at `0x1000_1107` (HARM slot 0): 30 values (-2OCT…USER)
- **AMP TYPE / SP TYPE**: 23 / 30 values, see `docs/effects/all_effects.md`

## Top-level workflows

### Patch load (click PRESET in left rail)

```
host → DT1 0x00000000 = 4 B  (patch select code; encoding non-trivial)
host → many RQ1s spanning 0x10000000..0x10003800 (~50 reads)
dev  → bulk DT1 stream filling the live edit buffer with the new patch
```

Full transcript: `captures/flows/preset_load.pcap` (93 events).

### Patch save (WRITE button)

```
host → DT1 0x10000000 = 16 B  (set patch name)
host → DT1 0x7F000104 = 2 B   (00 NN — save command, NN = slot index)
dev  → echoes 0x7F000104 = same 2 B
dev  → DT1 0x00000000 = 4 B   (patch-select register updated to slot)
host → DT1 0x7F000703 = 1 B   00  (clear dirty flag)
dev  → DT1 0x00200040 = 83 B  (patch-list metadata refresh)
host → RQ1 0x50000000 / 0x50000100 size=0x100  (refresh preset name table)
```

The user-patch slots at `0x6040_xxxx` are populated by the device
internally; the host doesn't transfer a bulk dump.

Full transcript: `captures/flows/write_save_v2.pcap`.

### Tuner activation (TUNER toolbar click)

```
host → RQ1 0x00000007 size=4
dev  → DT1 0x00000007 = current mode byte (1=MONO, 2=POLY, 3=TT)
host → DT1 0x00000007 = mode    (set tuner mode)
host → DT1 0x00000006 = 00      (sub-config)
host → DT1 0x7F000002 = 02      (editor-attached state = "tuner active")
dev  → DT1 0x7F000300 (48 B)    (start of real-time pitch display stream, repeats)
```

Tuner deactivates by writing `0x7F000002 = 01` (back to editor mode).

### Knob change (any effect parameter in the editor)

```
host → DT1 <param-addr> = <new byte value>
dev  → no echo for live-buffer writes (in-flight to audio engine)
```

Bulk read of a region:

```
host → RQ1 <addr> <size:4>
dev  → DT1 <addr> <data:size>     (or split into multiple DT1s by record boundary)
```

## Open questions / not yet captured

- **INITIALIZE** wire format — confirmed **client-side only** (no MIDI
  sent when the user clicks INITIALIZE in the WRITE menu). Tone Studio
  resets its local edit-buffer model to defaults; the device's edit
  buffer is unchanged until the user WRITEs or loads another patch.
- **CTL/EXP ASSIGN SETTINGS / KNOB SETTINGS / MEMORY MIDI** sub-tabs —
  empty default state; sub-controls only appear once a parent setting
  (ASSIGN SW, knob assignment, memory MIDI CH) is enabled. Addresses
  TBD until those parents are toggled.
- **MIDI PROGRAM MAP** — 64-row table, not yet exercised; addresses
  likely follow `0x0000_30xx` stride.
- **DEVICE SETTINGS** — only one address captured (`0x0020_0340`).
  Other LCD/USB driver/factory-reset settings TBD.
- **Patch-select register encoding** — 5 bytes at `0x0000_0000`
  encoding bank/sub-bank/preset; the table in `protocol.md` has
  partial coverage. Could be filled by `tools/probe_patch_select.py`.
- **Phase 6 factory reset** — explicitly deferred per user request
  (destructive; would wipe user patches).
- **Knob NAMES**: 79/81 effects have manual cross-reference; 8
  effects have count mismatches between captured knobs and manual
  TARGET list (see `tools/manual_xref.py` mismatches).

## Glossary

- **DT1**: Roland Data Set 1 — write or report data
- **RQ1**: Roland Request Data 1 — read request
- **TYPE**: per-effect sub-mode dropdown (e.g. AMP NATURAL/JC-120/…)
- **SP TYPE**: speaker simulator dropdown (AMP family only)
- **MODE**: alternative label for TYPE on some effects (DELAY_TWIST)
- **FUNCTION**: enum assignable to a footswitch / pedal slot
- **HARMONY**: one of 30 enum values for HARM/HARM_BASS' first knob
  (USER triggers HR1/HR2 user-scale rows)
- **MASTER**: per-patch master block (BPM, KEY, MEMORY LEVEL, etc.)
- **MEMORY**: a stored patch slot (User U01..U16 × 3, or Preset P01..)
